# IP Protection Notes

This document defines boundaries for using FIELDWAVE SF Policy Radar as a public portfolio artifact while continuing to improve the underlying product.

## Safe to Share

- The high-level problem statement and user pain point.
- The public architecture pattern.
- Credential-free dry-run commands.
- General descriptions of the taxonomy categories.
- The principle of preserving human judgment fields.
- Public-source data provenance from San Francisco Legistar pages.
- Lessons learned about workflow design and policy operations.

## Share With Caution

- Screenshots, only if all private notes, workspace URLs, database IDs, and stakeholder references are removed.
- Examples of matched records, only if sourced from public agenda data and stripped of internal commentary.
- Performance claims, only if they can be supported without revealing private operational data.
- Roadmap themes, only at a broad level.

## Keep Private

- API tokens, Notion database IDs, and environment variables.
- Private Notion pages, manual annotations, review notes, and stakeholder-specific context.
- Proprietary weighting, prioritization, scoring, or escalation refinements that are still under development.
- Commercial strategy, partnership targets, pricing assumptions, and funder-specific materials.
- Any non-public data sources or manually compiled datasets.

## Public Repository Hygiene Checklist

Before sharing a link publicly, confirm that:

- No .env files or credential-bearing logs are committed.
- Demo commands can run in dry-run mode without secrets.
- Documentation describes the workflow without exposing live private workspace details.
- Screenshots, if added later, are redacted and stored in a clearly public-safe location.
- The README and case study frame the project as a portfolio-safe prototype, not a complete disclosure of ongoing product strategy.
